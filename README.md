# chord-midi
rechord format to midi file

- [ ] optimize voicing

## CLI

web 版でできること（再生と逆引きを除く）は CLI からも使える。

    # 変換
    cargo run -p chord_midi_cli -- -i song.txt -o song.midi --bpm 120
    cargo run -p chord_midi_cli -- -i song.txt -o song.rechord

    # 編集（出力先を省くと書き換えた進行を標準出力に返す）
    cargo run -p chord_midi_cli -- -i song.txt --transpose -2
    cargo run -p chord_midi_cli -- -i song.txt --scale minor

    # 表示
    cargo run -p chord_midi_cli -- -i song.txt --print-ast            # 構文木 (JSON)
    cargo run -p chord_midi_cli -- -i song.txt --print-ast expanded   # 解決後 (JSON)
    cargo run -p chord_midi_cli -- -i song.txt --print-ast text       # rechord 記法に書き戻し
    cargo run -p chord_midi_cli -- -i song.txt --fingering
    cargo run -p chord_midi_cli -- --help-syntax                      # 記法の一覧

    # プリセット進行（`-i` の代わりに使う）
    cargo run -p chord_midi_cli -- --list-presets
    cargo run -p chord_midi_cli -- --preset 小室進行 --fingering

`--transpose` と `--scale` は AST ではなく入力テキストを書き換える。
web 版の移調ボタン / スケール選択と同じ扱いなので、結果をそのまま
入力ファイルに書き戻せる。

`--fingering` は web 版のコード図を等幅文字で描く。指は `1` = 人差し指、
`2` = 中指、`3` = 薬指、`T` = 親指。行頭の `o` は開放弦、`x` はミュート。

進行プリセットは `chord_midi/src/presets.rs`（`docs/progressions.json` からの
生成物）を web と CLI で共有している。

記法の一覧は `chord_midi/src/reference.rs`（手で足す静的テーブル）を web と
CLI で共有している。進行プリセットと同じ流儀。この README は記法の考え方と
代表的な例だけを書く。記号と関数を漏れなく見るには `--help-syntax` か web の
記法パネルを使う（表を書き写すとここだけ古くなるので、一覧はどちらか一方に
置く）。

## 記法パネル（エディタタブ）

エディタの右（狭い画面では下）に、記法を思い出さずに書くためのパネルがある。
GUI は独自の状態を持たず、**テキストを編集するだけ**なので、パネルで作った
ものは手で書いたものと区別がつかない。

- **定義** — テキストに書かれている `$名前 = ...` をボタンにする。押すと
  カーソル位置に `$名前` が入る。行頭を正規表現で拾うだけなので、打鍵の
  途中でパースが落ちていてもボタンは消えない
- **リズム** — 4 / 8 / 16 分割のマスを `o` → `.` → `x` と回して作る。
  「pat() を入れる」でカーソル位置に `pat("…", )` が入る。カーソルが既存の
  `pat("…")` の引用符の中にあるときは、パターン文字列だけが差し替わる
- **関数** — `pow` `oct` `pat` / `arp` `blk` `s25` `sub` `dom` と
  `( )` `( ) x2`。選択範囲があれば包み、無ければ雛形を入れてカーソルを
  括弧の内側に置く
- **記法の一覧** — 記号と関数の表。CLI の `--help-syntax` と同じものが出る

「進行プリセット」はエディタ側に残っていて、こちらは**テキストの末尾に
追記する**。パネルの定義ボタンは**カーソル位置に挿入する**。

## 押さえ方を直接書く（tab）

コード名ではなく押さえ方そのものを書ける。

    tab(8 6 6 x x x) |

- 6弦→1弦の順でちょうど6本。`x` はミュート、`0` は開放弦
- フレットは 0〜24
- MIDI は押さえた弦の実音をそのまま鳴らす。コード名を介さないので、
  押さえ方データの近似を通らない
- プレビューの見出しは逆引きした候補名。該当が無ければ記法がそのまま出る
- キーを上げ下げすると全弦が同じ数だけ動く。開放弦を含む形は下げられない
- `arp` `blk` `s25` `sub` `dom` は tab に掛けられない。コード名を持たない
  ため。`pat` は掛けられる（`x` のスロットはブラッシングになる）。
  `pow` `oct` は小節列に掛かる関数なので書けるが、tab には何も効かない

指板の「挿入」が入れるのもこの記法で、押さえた形がそのまま戻る。

## 逆引き（指板）

エディタタブの textarea の下にある指板では、クリックして作った押さえ方から、
それが何のコードで rechord 記法ではどう書くのかを引ける。

- 指板を押すとその弦の音が決まる。1弦につき1音で、同じところをもう一度押すと
  その弦はミュートになる
- 候補は確度の高い順に最大5件。バッジの「原典」は押さえ方データに同じ形がある
  もの、「計算」は鳴っている音から名前を出しただけのもの
- 「挿入」を押すと、`tab(...)` の形でカーソル位置に入る。押さえた形が
  そのまま戻るので、図と指板が食い違わない

## コード表タブ

コード名から押さえ方を見る。進行を書かずに「`C#m7` ってどう押さえるの？」を
引くための画面。

「格子」と「簡単コード」を切り替えて使う。

- **格子** — 12ルート × 11品質 (`(maj) m 7 m7 M7 m7b5 sus4 6 add9 dim aug`)。
  どのコード名でも引けるが、原典にその名前の形が無いときは近似の形が出る。
  そのときは見出しに `(≒ 原典名)` が付く
- **簡単コード** — 押さえ方データにある67形をそのまま並べる。原典の
  「Cコード系」などのグループごと。近似が起きないので `(≒ )` も出ない。
  同じ名前で押さえやすさ違いの形があるものは `C` / `C (2)` と連番が付く

ボタンを押すと下の指板にその押さえ方が出る。指が分かっている形では
ドットの中に `人 / 中 / 薬 / 親` が入る。この指板は表示専用で、
クリックからの逆引きはエディタタブの指板にある。

## 押さえ方データ

ギターの押さえ方は `docs/easy_guiter_chords.json` が原本。
運指の導出と Rust テーブルの生成は次で行う。

    just gen-fingerings

`chord_midi/src/fingering/data.rs` は生成物なので手で編集しない。

## キーとスケール

    key: C
    scale: dorian

`key:` と `scale:` は**それ以降の行に効く**。曲の途中で書き直すと、そこから
後ろだけがそのキーになる。

    key: C
    I | IV |
    key: D
    I | IV |     # ここは D のキーで解釈される

`--print-ast` と web 版の「解釈結果」で、この入れ子が JSON として見える。

## 定義と参照

`$名前 = ...` で進行やリズムに名前を付け、`$名前` で呼び出せる。
定義行は曲に小節を足さない。**定義行以外のすべてが曲**になる。

    key: C
    $eight = "o.o.o.o."
    $riff  = pow(C | E D)
    $A     = pat($eight, C | Am | F | G)
    $B     = $riff x2 | pat($eight, F | G)

    $A x2 | $B | $A

最後の1行が曲の本体で、これで 18 小節になる。

- 定義は行頭に書く。本体は1行
- 名前は英数字・`_`・日本語が使える（`$Aメロ`）
- 使う前に定義する。前方参照・循環参照・同じ名前の二重定義はエラー
- `$名前` は小節の位置、`pat` の第1引数、関数や `( )` の中に書ける
- 定義が小節より後ろにあると警告が出る（エラーではないので再生は止まらない）
- 定義行にも行末コメントを書ける (`$eight = "o.o.o.o."  # 8分の刻み`)

`$名前` は中身をその場に貼り付けるだけなので、定義を使って書いても
手で展開して書いても同じ MIDI になる。

### キーは使う位置で決まる

度数表記のリフを定義しておくと、キーを変えて使い回せる。度数が実音に変わるのは
定義した位置ではなく**使う位置**なので、同じ `$a` がキーごとに違う音になる。

    key: C
    $a = I | IV |
    $a          # C | F |
    key: D
    $a          # D | G |

### 繰り返し

`xN` は直前の1項目を N 回繰り返す。`N` は 2〜32 で、範囲外はパースエラー。

    C | Am x3 |          # C, Am, Am, Am （直前の小節だけ）
    $A x2 | $B           # A A B

`( )` で範囲を明示できる。

    (C | Am | F | G) x4  # 4小節を4回で 16 小節

展開後の小節数には 4096 小節の上限がある。`$b = $a x32` のような入れ子は
乗算的に増えるので、打ち間違い1つで膨れ上がるのを防いでいる。

## 関数

    arp(C)              アルペジオ
    blk(F)              ブラックアダーコード
    s25(G7)             ツーファイブ分割
    sub(G7)             裏コード化
    dom(Dm7)            ドミナント化

小節列を引数に取る関数もある。

    pow(C | E D)              パワーコード化（ルートと5thだけ鳴らす）
    oct(A | G#)               オクターブ奏法（ルートと1オクターブ上のルート）
    pat("o.o.oxox", C | E D)  リズムパターン
    pat("oxox", pow(C))       ネストできる

`pat` のパターンは `o` が打弦、`.` が休符、`x` がブラッシング。
文字数が1小節の分割数になり、1/2/4/8/16 のいずれかだけ書ける。

### 関数の入れ子

コードを引数に取る関数は、返すものが2種類ある。**コードを返す関数だけが、
コードを引数に取る関数の中に書ける。**

| 関数 | 返すもの | コードの位置に置けるか |
|---|---|---|
| `blk` `sub` `dom` | コード | 置ける |
| `arp` | 鳴らし方（アルペジオ） | 置けない |
| `s25` | 鳴らし方（尺を2つに割る） | 置けない |

| 書ける | 書けない |
|---|---|
| `arp(blk(F))` | `arp(s25(G7))` — `s25` はコードを返さない |
| `blk(sub(G7))` | `blk(arp(C))` — `arp` はコードを返さない |
| `s25(blk(F))` | `s25(s25(G7))` |
| `arp(blk(sub(G7)))` | `blk(s25(G7))` |
| `pat("oxox", arp(blk(F)))` | `arp(arp(C))` |

「書けない」側は**パースエラー**になる。実行時に無視されるのではなく、
そもそも読めない。`arp` と `s25` がコードの位置に置けないだけなので、
小節列を引数に取る `pow` / `pat` の中には書ける
（表の `pat("oxox", arp(blk(F)))` がそれ）。

入れ子は「中の関数の結果を手で書いたもの」と同じ MIDI になる。
`blk(F)` は `Baug/F` になるので、`arp(blk(F))` は `arp(Baug/F)` と同じ。

### 弦指定

コードの末尾に `@N` (N = 1〜6) を書くと「最低音をこの弦で取る」という
押さえ方への指示になる。音程には影響しない。`/on` より後ろに置く。

    pow(A@6 | D@5 | E@5)    6弦5fr / 5弦5fr / 5弦7fr のパワーコード
    A/E@6 |

指定した弦を最低音にする押さえ方がデータに無いときは「データなし」になる。
今のデータで最低音になり得るのは 6弦 / 5弦 / 4弦 だけなので、実質 `@6` と
`@5`（一部 `@4`）が使える。

`pow()` と `oct()` はそれぞれ専用の押さえ方（12キー × 6弦/5弦ルート）を持つ。
`oct()` は間の弦をミュートする。

    pow(A@6)    6弦5fr + 5弦7fr    (A2 + E3)
    oct(A@6)    6弦5fr + 4弦7fr    (A2 + A3)
    oct(A@5)    5弦0fr + 3弦2fr    (A2 + A3)
