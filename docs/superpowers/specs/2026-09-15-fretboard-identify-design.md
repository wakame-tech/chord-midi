# 指板クリックからのコード逆引き 設計

日付: 2026-09-15

## 目的

今の web は「コード進行を書く → 押さえ方が出る」の一方向しかない。逆、つまり
「指板でこう押さえた → これは何のコードで、この記法でどう書くのか」が引けない。

ギターを触りながら見つけた形を rechord 記法に落とす手段が無いので、3つ目のタブ
「運指」を足して、指板をクリックするとコード名候補と記法が出るようにする。

## 決定事項 (ユーザー確定)

| 論点 | 決定 |
| --- | --- |
| 照合方法 | 押さえ方データ照合 + 理論計算の併用 |
| 指板の範囲 | 6弦 × 0〜12フレットを横長に全部出す |
| クリック | 1弦1音。同じセル再クリックでその弦をミュート |
| タブ | 3つ目のタブ「運指」 |
| 出力 | コード名候補リスト（確度順）+ rechord 記法（エディタに挿入） |
| CLI | 今回は web だけ。ロジックは `chord_midi` に置いて後で足せるようにする |

## 全体の流れ

```
指板クリック
  -> [Option<u8>; 6]           6弦->1弦、None=ミュート、Some(0)=開放
  -> fingering::identify()
       段0: 鳴る音のピッチクラス集合と最低音を出す
       段1: FINGERINGS を frets 完全一致で照合（当たれば原典名と kind が分かる）
       段2: 12ルート × 品質テーブルを ChordNode で組み立てて採点
       段3: 候補ごとに記法を決める（pow/oct の包み、@N の要否、往復検証）
  -> Vec<Candidate>            上位5件
  -> カード表示 + 「エディタに挿入」
```

### 段1の名前を記法に使わない理由

`Fingering.name` は原典（daichan easy guitar）の表記で、rechord の記法ではない。

```
A♭△7    Am7-5    D7(9)    B♭add9/D
```

`△` や `-5` や `(9)` は rechord のパーサに通らない。型の doc コメントにも
「表示用で、照合には使わない」と書いてある。なので**記法は必ず段2が組み立てた
`ChordNode` から作る**。段1のデータ照合は、

- その形が原典に載っているか（＝ `Source::Data` のバッジ）
- 原典での呼び名（副表示）
- 可動形なら `pow()` / `oct()` のどちらで書くか

を決めるためだけに使う。

## 逆引きロジック

新設 `chord_midi/src/fingering/identify.rs`。`find()` の逆なので同じモジュールに置く。

```rust
/// 候補がどこから来たか
#[derive(Debug, Clone, PartialEq)]
pub enum Source {
    /// 押さえ方データにこの形があり、記法もこの形を再現する。
    /// 中身は原典での呼び名（"A♭△7" など、rechord の記法ではない）
    Data(&'static Fingering),
    /// 鳴る音から計算しただけ
    Theory,
}

#[derive(Debug, Clone, PartialEq)]
pub struct Candidate {
    /// rechord のコード名。"C" や "C/E"
    pub name: String,
    /// そのまま入力に書ける記法。"C/E@6" や "pow(A@6)"
    pub notation: String,
    pub source: Source,
    /// `notation` を書いても押さえた形には戻らない（記法で表せない形）
    pub unreachable: bool,
    /// 小さいほど良い。表示順に使う
    pub score: u32,
}

/// 押さえ方からコード名候補を引く。frets は 6弦->1弦、None = ミュート
pub fn identify(frets: [Option<u8>; 6]) -> Vec<Candidate>;
```

### 段0: 鳴る音の取り出し

```rust
/// 開放弦の MIDI ノート番号。6弦->1弦。今は fingering/mod.rs のテスト内に
/// 同じ定数があるので、テスト外に出して pub にして共有する
pub const OPEN_STRING_PITCHES: [u8; 6] = [40, 45, 50, 55, 59, 64];
```

弦 `s` のフレット `f` が鳴らす MIDI ノートは `OPEN_STRING_PITCHES[s] + f`、
ピッチクラスは `(OPEN_STRINGS[s] + f) % 12`。

最低音は**実 MIDI ピッチの最小値**から取る。`Fingering.bass` は「鳴る弦のうち
一番低い弦」で定義されているが、これは原典データがローポジションばかりだから
成り立っている近似で、自由にクリックできる指板では破れる。

```
6弦12fr = E3 (52)   5弦開放 = A2 (45)   -> 弦番号が小さい方が高い
```

鳴る弦が0本なら空の `Vec` を返して終わり。

### 段1: データ照合

`FINGERINGS` を `f.frets == frets` の完全一致で走査して `Option<&'static Fingering>`
を得る。ここでは名前を作らない。使うのは `kind` と、後で副表示に出す `name` だけ。

### 段2: 理論計算

品質テーブルを定数で持つ。文字列は書かない。`ChordNode` を組み立てて既存の
`chord_ref()` に食わせ、構成音と表示名の両方を既存コードから得る。こうすると
出した記法は必ずパーサに通る（`ChordNode` の `Display` が記法そのもの）。

**テーブルは「追加の修飾」だけを書く。** `chord_node_parser` は必ず
`Modifier::Major(5)` を種として入れてから読んだ修飾を足すので、`identify` 側も
同じように種を入れる。そうしないと `Sus4` 単体のように「既存の3rdを消して4thを
入れる」修飾が土台の無いところに当たって壊れる。

```rust
/// 逆引きで当てにいくコードの品質。Major(5) は chord_node_parser と同じく
/// 常に種として入れるので、ここには書かない。
/// 上から「よくある」順で、同点のときはこの順が優先される
const QUALITIES: &[&[Modifier]] = &[
    &[],                          // C
    &[Modifier::Minor(5)],        // Cm
    &[Modifier::Dominant(7)],     // C7
    &[Modifier::Minor(7)],        // Cm7
    &[Modifier::Major(7)],        // Cmaj7
    &[Modifier::Sus4],            // Csus4
    &[Modifier::Sus2],            // Csus2
    &[Modifier::Dominant(6)],     // C6
    &[Modifier::Add(9)],          // Cadd9
    &[Modifier::Dominant(9)],     // C9
    &[Modifier::Minor(9)],        // Cm9
    &[Modifier::Major(9)],        // Cmaj9
    &[Modifier::MinorMajaor7],    // CmM7
    &[Modifier::Minor(7), Modifier::Flat5th],  // Cm7b5
    &[Modifier::Dim],             // Cdim
    &[Modifier::Dim7],            // Cdim7
    &[Modifier::Aug],             // Caug
    &[Modifier::Power],           // C5（記法は pow(C)。下記参照）
];
```

入れない品質と理由:

- **m6**: `Modifier::Minor(6)` はマイナースケールの6度 = b6 を足す。実際の m6
  コードは長6度なので、今の `Modifier` では正しく組めない。逆引きが間違った
  名前を出すより出さない方が良い
- **oct**: 構成音がルート1音だけなので、どの1音を押さえても完全一致して候補を
  埋め尽くす。オクターブ形は段1のデータ照合で拾う（データが12キー × 6弦/5弦
  ルートを網羅しているので取りこぼさない）

12ルート × 18品質 = 216 通りを毎クリック回す。wasm でも一瞬なのでキャッシュ
しない。

各候補について:

1. `modifiers = BTreeSet::from([Major(5)]) ∪ quality` の `ChordNode` を作る
2. `chord_ref(&node)` で `label` と `pitch_classes` を得る
3. 押さえた集合と突き合わせて採点する

スラッシュは、最低音のピッチクラスがルートと違い、かつ押さえた集合に含まれる
とき `on: Some(Key::Absolute(bass))` を立てた版も候補に入れる。`on` 有り・無し
の両方を出して採点に任せる（`C/E` と `C` はどちらも正しい呼び方で、どちらが上に
来るかはスコアが決めるべき）。

### 採点

既存の `missing_cost` / `extra_cost` をそのまま使う。今は `fingering/mod.rs` の
private なので `pub(crate)` に上げるだけ。

```
score = 押さえた音にあってコードに無い音の extra_cost 合計
      + コードにあって押さえた音に無い音の missing_cost 合計
      + ルートが鳴っていなければ +3
      + 最低音 != ルート かつ on 無しなら +2
      + 自分のルート以外がベースに来るパワーコードなら +2
```

最後の項の理由。パワーコードは2音しか無いので、たいていの押さえ方に素点 0 で
当たってしまい、まともな名前を押しのける。`x3x34x` が鳴らす `{C, D#, A#}` に
`D#5/C`（D# パワーコードを C の上に乗せた形）がちょうど当たる、といった具合。
だがこれを「D# パワーコード on C」と読む人はいない。5th を省いた `Cm7` と読む。
一方で `x3x01x` の `{C, G}` を `C5` と読むのは自然なので、**自分のルートに
乗っている**パワーコードは罰しない。

点の大きさは 115 形すべてで測って決めた。1〜4 のどれでも先頭の候補は変わらない。
1 だと実際の名前と同点になって勝敗が QUALITIES の並び順のタイブレーク頼みに
なるので、点そのもので決まる最小値として 2 を採った。

足切り: 押さえた音のうちコードで説明できない音が2つ以上ある候補は落とす
（`find()` が逆向きに1つまで許すのと同じ考え方）。

並べ替えは `(score, QUALITIES での並び順)`。
同じ `name` が複数出たら最初の1件だけ残す。最終的に上位5件。

段1で当たった形を再現する候補を先頭に持ち上げることは**しない**。それをやると
`3x003x` の `{G, D}` で、素点 4 の `Ddim/G` が素点 0 の `G5` を押しのけて
先頭に来てしまう（`Ddim/G` と書けば確かにこの形に戻るが、コード名としては
おかしい）。段1との一致は `Source::Data` のバッジで伝えるだけにして、
並び順は採点に委ねる。

### 既知の限界: 2音の形は先頭が原典名にならないことがある

パワーコードの罰則で直るのは「パワーコードが安く刺さる」場合だけで、音数の
少ない形に3音の品質が安く刺さるケースは残る。115形で1つだけ残っている:

```
x234xx   原典は Bdim   鳴るのは {B, F} の2音
  1位  Fsus4/B  素点 2
  2位  Bdim     素点 3   ← D が鳴っていないぶん missing_cost(3) = 3 を引く
```

`Fsus4/B` はパワーコードではないので罰則が届かない。2つ目のヒューリスティックを
足せば直せるが、115形すべてを測り直す必要があり、退化した2音の形1つのために
入れる価値は無いと判断した。`Bdim` は候補リストには出ている。

### 段3: 記法を決める

段1で当たった押さえ方の `kind` で分岐する。

**`Power`**: `C5` と書いても `Modifier::Dominant(5)` に読まれてただのメジャー
トライアドになる（`Modifier::Power` は `pow()` からしか作れない）。なので
ルートが一致する候補の記法を `pow(<ルート>@N)` に差し替える。`@N` は
`6 - f.lowest_string`（`chord_ref()` の逆変換）。可動形は「どの弦で取るか」が
形そのものなので `@N` は常に付ける。

**`Octave`**: 同様に `oct(<ルート>@N)`。段2は oct を出さないので、この候補は
段3で足す（`name` は `<ルート>oct`、`score = 0`）。

**`Modifier::Power` を持つ候補すべて**: 段1に当たったかどうかに関係なく、記法は
`pow()` で包む。`Power` を外した中身を `ChordNode` の `Display` に通してから
括弧に入れるので、`D5` は `pow(D)`、`D#5/C` は `pow(D#/C)`、`@N` 付きは
`pow(D@4)` になる（`@N` は `Display` が末尾に付けるので自然と括弧の内側）。
包み忘れると、書いた記法が別のコードに読み直される。`name` は `D5` のままでよい
（名前としては正しく、直す必要があるのは記法だけ）。

**`Normal` / 段1が外れたとき**: 往復検証で `@N` の要否を決める。

```
1. 候補の ChordNode（@N 無し）を chord_ref() -> find() に流す
2. 返った押さえ方の frets がクリックした形と同じ  -> @N は要らない
3. 違う -> root_string = 6 - 最低音の弦 を立てて再試行
4. それでも違う -> 記法は @N 無しの名前のまま、unreachable = true
```

`unreachable` が立つのは「その形は今のデータでは再現できない」ということ。記法
としては正しい（音は合っている）ので書けるが、プレビュータブに戻したとき同じ形
にはならない。UI でその旨を添える。

`Source::Data(f)` を立てるのは、段1が当たっていて、かつその候補の記法が
クリックした形を再現した（= 2 か 3 で止まった）ときだけ。

## web UI

### 指板

```
            0     1     2     3     4     5    ...   12
  1弦  ○  ║     │     │     │     │     │          │
  2弦  1  ║  ●  │     │     │     │     │          │
  3弦  ○  ║     │     │     │     │     │          │
  4弦  2  ║     │  ●  │     │     │     │          │
  5弦  3  ║     │     │  ●  │     │     │          │
  6弦  ×  ║     │     │     │     │     │          │
                         ▲3          ▲5    ...   ▲12
```

- 1弦を上に描く。プレビュータブのコード図と同じ向き
- 左端の列は現在値の表示だけ（`×` / `○` / フレット番号）。クリック対象ではない
- 0列は開放。ナットの左側に置く
- セルクリックで `frets[s] = Some(f)`。同じセルをもう一度押すと `None`（ミュート）
- 1弦につき点は1つ。別のフレットを押すと前の点は消える
- 初期状態は全ミュート。「クリア」ボタンで戻せる
- フレット番号は `diagram.rs` の `POSITION_MARKS` を再利用して 3/5/7/9/12 に出す
  （`POSITION_MARKS` は今 `diagram.rs` の private なので `pub(crate)` に上げる）
- 横に長いので、狭い画面では横スクロールさせる

### 状態

`[Option<u8>; 6]` は `App` が `use_state` で持つ。タブは条件レンダリングで
アンマウントされるので、`Fretboard` の内部に持つとタブを離れた時点で消える。

`Fretboard` に渡す props:

- `frets: [Option<u8>; 6]`
- `on_change: Callback<[Option<u8>; 6]>`
- `on_insert: Callback<String>` — 記法を入力テキスト末尾に追記する。既存の
  プリセットボタンと同じ挙動

### 候補の表示

候補1件を1カードにする。

```
┌──────────────────────────────┐
│ C                      原典  │
│ 原典での呼び名: C            │
│ C                    [挿入]  │
└──────────────────────────────┘
┌──────────────────────────────┐
│ Am7                    計算  │
│ Am7                  [挿入]  │
│ この形は今のデータでは再現できない │
└──────────────────────────────┘
```

- 1行目: rechord のコード名と出典バッジ（`原典` = `Source::Data` /
  `計算` = `Source::Theory`）
- `Source::Data` で原典名が rechord 名と違うときだけ、原典での呼び名を出す
  （`diagram.rs` の `≒` 併記と同じ考え方）
- 記法と「挿入」ボタン
- `unreachable` のときだけ注記を出す
- 候補が0件（全ミュート、または足切りで全滅）のときは「該当なし」

## テスト

`identify.rs` の単体テスト。フレット列は `x32010` のような原典と同じ書き方の
文字列をテストヘルパでパースして作る（`x` = ミュート、それ以外は1桁の16進）。

| ケース | 期待 |
| --- | --- |
| `x32010` | 先頭候補の `name` が `"C"`、`source` が `Data`、`notation` が `"C"` |
| `022000` | 先頭候補の `name` が `"E"` |
| `x02220` | 先頭候補の `name` が `"A"` |
| 6弦5fr + 5弦7fr（他ミュート） | 先頭候補の `notation` が `"pow(A@6)"` |
| 6弦5fr + 4弦7fr（他ミュート） | 先頭候補の `notation` が `"oct(A@6)"` |
| 全弦ミュート | 空の `Vec` |
| `x3555x`（データに無い形、C の高い位置） | 候補が1件以上出て、先頭が `"C"`、`source` が `Theory` |
| 候補は5件以下 | どの入力でも `len() <= 5` |
| 名前の重複が無い | 返った候補の `name` に重複が無い |
| 往復（全データ） | `FINGERINGS` の全要素について `identify(f.frets)` が1件以上返し、`Source::Data` の候補の `notation` をパースして `find()` に流すと `f.frets` と同じ形が戻る |

web 側は既存のコンポーネント同様テストを書かない。`trunk build` が通ることを
確認する。

## スコープ外 (YAGNI)

- CLI の `--identify`。ロジックは `chord_midi` に置くので後から足せる
- 押さえた形の試聴（MIDI 再生）
- 構成音と度数の内訳表示
- 指の割り当て推定。逆引きではどの指で押さえたか分からないので点だけ描く
- 12フレットより上。オクターブ上は同じピッチクラスなので逆引きの答えは変わらない
- m6 と、`Modifier` で正しく組めないその他の品質
- 押さえた形の保存・共有
